1. Start a server

The game, the host mode and the dedicated server are the same program. A dedicated server runs without a window and keeps the world running while nobody plays on that PC.

Windows

  1. Open the game folder.
  2. Double-click start-server.bat. A terminal window opens and shows the log.
  3. Allow Spacebox in the Windows Firewall question (also on public networks if you want players from outside).

Linux

  1. Unzip the Linux build.
  2. Run ./start-server.sh in a terminal.
  3. No desktop, X11, Wayland or graphics card is needed: the server runs without a window.

On the first start the server creates Multiplayer/serverconfig.json and a new world in Worlds/ServerWorld. When the log shows World ready, players can join.

Stop the server safelyType stop in the terminal (or use Stop in the dashboard). The world is saved first. Ctrl+C, closing the terminal window and a system stop signal (SIGTERM, for example from systemd or Docker) also save before the server stops (Windows waits only about 5 seconds when the window is closed). Killing the process loses changes since the last autosave.

Without the scripts: Spacebox.exe --server (Windows) or ./Spacebox --server (Linux).

2. The config file

serverconfig.json lies in the Multiplayer folder next to the executable (together with this guide). Edit it while the server is stopped (most settings can also be changed live in the dashboard). Missing settings are added with their defaults on the next start. Setting names may be written in any case, // comments and a trailing comma are allowed, and Seed may be a number or a text. If the file cannot be read (for example a JSON typo), the server starts with default settings but does not overwrite it: it logs an error and keeps a copy as serverconfig.json.broken; fix the file and restart.

3. Join the server

  • Same network: Multiplayer menu → the server appears under local servers (servers on ports 7777 to 7786).
  • By address: add a server with the IP (or DuckDNS name) and port 7777.
  • Same PC: address 127.0.0.1.

Players get the server's GameSet automatically if they do not have it. The game version must be the same on server and clients: the server list shows the server's version in red when it differs, and joining it says which version the server runs. A game opened with "Open to network" uses port 7777, or the next free port up to 7786 when 7777 is taken (for example by a server on the same PC); the pause menu shows the port.

4. Open it to the internet

  1. Fixed LAN address: give the server PC a fixed local IP in your router (DHCP reservation), e.g. 192.168.1.50.
  2. Port forwarding: in the router forward UDP 7777 (game) and TCP 7777 (dashboard) to that IP. Some routers have one rule for "TCP/UDP".
  3. Firewall: Windows: allow Spacebox when asked, or add inbound rules for TCP and UDP 7777. Linux with ufw: sudo ufw allow 7777.
  4. A name instead of an IP: home IPs change. A free DuckDNS name is easiest (chapter 5): the server keeps it up to date by itself. Any other name service works too.
CGNATIf the WAN/Internet IP in your router differs from the IP that duckdns.org shows for you, your provider uses CGNAT and port forwarding cannot work. Ask the provider for a public IPv4 address, or use a VPN/tunnel service (for example a VPS or a mesh VPN for your friends).
Inside your own networkMany routers cannot open your own public name from inside (no "NAT loopback"). At home use the LAN address, e.g. 192.168.1.50:7777; friends outside use the DuckDNS name.

5. Automatic HTTPS

The dashboard asks for your admin password. Over the internet it must be encrypted (HTTPS), otherwise the password can be read on the way. The server gets a free certificate from Let's Encrypt and renews it by itself. You only tell it the address people use, and pick one of the ways below.

Your situationWhat to put in serverconfig.jsonExtra port
Free DuckDNS namePublicAddress + DuckDnsTokennone
Own domain on CloudflarePublicAddress + CloudflareApiTokennone
Any other name (No-IP, Dynu, own domain, …)PublicAddressTCP 80
Only your public IPPublicAddress = the IPTCP 80

A. DuckDNS (easiest, free)

  1. Open https://www.duckdns.org, sign in and add a sub domain, for example myserver.
  2. Copy the token shown at the top of the page.
  3. Stop the server and set: 
    "PublicAddress": "myserver.duckdns.org",
"DuckDnsToken": "a1b2c3d4-....-your-token"
  4. Start the server. The server also keeps the name on your current IP, so the DuckDNS updater program is not needed.

B. Your own domain on Cloudflare

  1. In Cloudflare, add a DNS record (A) like play.example.com → your public IP, proxy off (grey cloud).
  2. My Profile → API Tokens → Create Token → template Edit zone DNS, zone = your domain. Copy the token.
  3. Set: 
    "PublicAddress": "play.example.com",
"CloudflareApiToken": "your-cloudflare-token"

C. Any other name or just your IP

  1. Make sure the name points to your public IP (No-IP, Dynu and others have their own small updater program).
  2. Forward TCP 80 to the server PC as well (Let's Encrypt checks a file there; the server opens port 80 only for those few seconds).
  3. Set: 
    "PublicAddress": "play.example.com"     or your IP, e.g. "85.10.20.30"
Port 80 not possible?Some providers block it, and on Linux only root may open ports below 1024. Forward external port 80 to another internal port in the router (for example 8080) and set "HttpsChallengePort": 8080. If your provider blocks port 80 completely, use DuckDNS or Cloudflare instead.
Only an IP addressLet's Encrypt gives certificates for IP addresses that last about 6 days; the server renews them automatically every few days. If your IP changes, a name (DuckDNS) is the better choice.

Then

Start the server. After about a minute the log shows HTTPS certificate for … saved, and the dashboard overview shows the HTTPS state. Open https://<your address>:7777/dashboard from anywhere.

What happens in the backgroundThe certificate is stored in Multiplayer/Dashboard/certificates/, checked every 12 hours and renewed when a third of its time is left (30 days for normal certificates). Failures are written to the log with a hint and retried after an hour. Set "LetsEncryptStaging": true for a first test run: Let's Encrypt then issues test certificates (browsers warn about them) and failed attempts do not count against its limits.
Keep tokens secretDuckDNS and Cloudflare tokens control your name. Do not share serverconfig.json or screenshots of it.

While HTTPS is active, plain http:// still works inside your own network; from the internet it is redirected to https://. Without HTTPS the dashboard refuses plain http:// from the internet unless DashboardAllowPublicHttp is true. The dashboard only answers addresses it knows (IP addresses, local names, PublicAddress and the certificate names); for another domain name set it as PublicAddress. Using your own certificate instead: set DashboardCertificateFile and DashboardCertificateKeyFile.

6. The web dashboard

First start: create the admin

  1. Start the server. The log says: No admin yet. Register in the dashboard with the setup key from …/Multiplayer/Dashboard/setup-key.txt.
  2. Open the dashboard: on the server PC http://localhost:7777/dashboard, in your network http://192.168.1.50:7777/dashboard (the server log prints the exact local addresses at start; Windows Firewall on the server PC must allow the server, TCP port 7777 for the dashboard), from outside https://<your address>:7777/dashboard.
  3. Open Multiplayer/Dashboard/setup-key.txt in the server folder and copy the key (like ABCDE-FGHJK-LMNPQ-RSTUV).
  4. Enter the key, an admin name and a password (at least 8 characters). The key file is deleted; only one admin exists.
Forgot the password?Stop the server, delete Multiplayer/Dashboard/admin.json and start again: a new setup key is written and you can register again.

7. Console commands

Type them in the server terminal or the dashboard console. help lists all of them. Admins (see Admins in chapter 2) type them in the game chat with a leading /; the answer appears only in their own chat. Other players cannot run server commands and cannot change their own game mode. Pressing / in the game opens the chat with / already typed; /help lists the commands of the game client. While typing, the chat suggests commands, player names, item and mob ids: Tab completes, Up/Down picks a suggestion or browses earlier messages. In chat the player name is optional for give, heal, health, power, air, set, hit, skin, kill, gm and mob: without it the command applies to yourself. A command typed without the arguments it needs answers with its usage.

Claim beacons (player protection)

Players craft a Claim Beacon and place it on their ship (protects the whole ship) or their base on an asteroid (protects a cube of ±Radius blocks around it; the rest of the asteroid stays free to mine). They pay with ingots in the beacon's slot; every ingot adds protection time, up to the stored maximum. While time is left, only the owner, the members the owner adds in the beacon window and admins can build, break, open blocks or fly the ship there; doors still work for everyone, and bullets, bombs and collisions do no damage. When the time runs out, the area is free again, so abandoned claims disappear by themselves. Time only runs while the area is loaded on the server. Claims cannot overlap another player's active claim; /protected lists the loaded claims.

BackupsThe Overview page of the dashboard lists the backups and has a Back up now button. To restore one, stop the server and unpack the zip in place of the world folder. Updating the game: copy the new game files over the old ones, keep Multiplayer/, Worlds/ and Mods/. Older installs with serverconfig.json, dashboard/ and GameSets/ next to the executable are moved into the new folders on the first start. Worlds from 0.1.2 are converted automatically on the first start (a backup is made first); older worlds cannot be converted.
