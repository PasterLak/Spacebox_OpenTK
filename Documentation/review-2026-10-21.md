# Code review notes (2026-10-21)

Most findings of the review are fixed (see `Spacebox/DONE.txt`, 0.1.5, and the "Server checks" note in `spec.md` §8). Still open:

## Multiplayer

1. **Inventories are still client-side.** Drops and container deposits are now limited (stack size, distance, rate), but a modified client can still put items it never had into a chest or its own inventory. A real fix is server-authoritative inventories (hotbar, inventory, equipment, crafting, building and drops send intents to the server).
2. **Health is decided by the owner.** Damage is applied by the hit player's client and death is an owner-written variable, so god mode is possible. Needs server-side health (damage, healing items, oxygen, fall damage) with the client only predicting.
3. **Mob spawner items** are not checked against the inventory (needs 1); only a global cap of 96 mobs exists.
4. **Block removal and damage have no range check**, because projectiles legitimately break blocks far away. A check against the shooter's projectile simulation on the server would close this.
5. Movement checks are soft: a client can still move up to 60 m/s anywhere, and creative/spectator players are not checked.

## Game

1. Translucent blocks: the transparent pass covers models and particles; chunk meshes still draw transparent blocks as cutout. Real glass needs a separate per-chunk transparent mesh drawn through `TransparentQueue`.
2. Transparent models with `FadeMaterial`/`TransparentMaterial` (not particles) can still get SSAO on top; they would need the same AO mask pass as particles.
3. The UI showcase uses ~130 draw calls because every item icon is its own texture; with the game's item atlas it would be a few.

## Environment notes from testing

- WSL on this PC fell back to "no NAT" networking, so a Windows client cannot reach a server running inside WSL. The Linux server itself works.
- Linux players need `libopenal1` for sound; without it the game runs muted.
