# Engine — architecture notes for agents

Game-independent engine over OpenTK (GL 3.3 core). Namespace `Engine.*`. Must never reference `Spacebox.*`. Coding rules: see root `CLAUDE.md`.

## Lifecycle (`EngineWindow.cs`)

Hooks for the game subclass (`Spacebox/SpaceboxWindow.cs`):
- abstract: `OnRegisterScenes`, `OnGameLoad`
- virtual: `OnSetupInput`, `OnSetupPostProcessing(PostProcessManager)`, `OnRenderGameGUI`, `OnUpdateInput`, `OnPostRender`

Before the window is created the game calls `Platform/GpuSelection.PreferDedicatedGpu()` (rules in `GpuSelectionRules`, tested): on Windows it loads `nvapi64.dll` (NVIDIA Optimus then uses the dedicated GPU) and sets the per-exe Windows graphics preference to high performance (`HKCU\Software\Microsoft\DirectX\UserGpuPreferences`, only when the player chose nothing, never for `dotnet.exe`); on Linux with two GPUs it sets the PRIME offload variables (`__NV_PRIME_RENDER_OFFLOAD` + `__GLX_VENDOR_LIBRARY_NAME` with the NVIDIA driver, else `DRI_PRIME=1`) unless already set. Dedicated servers skip it.

`OnLoad` order: `Input.Initialize` → `ResourceFallbacks.Initialize` → `LightSystem.InitializeGpu` → `VisualDebug.InitializeGpu` → `SceneRenderer` → system report in the log (`Core/Diagnostics/SystemReport` + `CpuName`: game version, OS, .NET, CPU, cores, RAM, GPU/driver/OpenGL/GLSL, monitor; no GPU lines headless) → `FrameLimiter` → `SceneManager.Initialize(OnRegisterScenes)` → default F-key bindings → `OnSetupInput` → `PostProcessManager` → `OnSetupPostProcessing` → `OnGameLoad`.

`OnUpdateFrame`: `SceneManager.ApplyPendingSceneChange` → `RenderSpace.BeginFrame` → `InputInjector.Apply` → `Input.Update` → `Time.Update` → `InputManager.Update` (InputPro) → `InputManager0.Update` → drain main-thread action queue → `OnUpdateInput` → `SceneManager.Update` → `GlobalUniforms.Push` → `AudioDevice.Update`.

`OnRenderFrame`: `LightSystem.Update` → `SceneRenderer.Render` (into FBO: `Scene.Render` draws skybox, then `BVHCuller.Render(scene, Camera.Main)`; then `VisualDebug.Render`) → backbuffer + `PostProcessManager.Process` → GUI (`WorldDebugView.DrawWorld`, `Scene.OnGUI`, `DevConsole.Update`, `Overlay.Update`, `DevPanel.Update`, `OnRenderGameGUI` while a scene is loaded, then `WorldDebugView.DrawLabels`, `Overlay.Draw`, `DevPanel.Draw` and `DevConsole.Draw` on top) → `MainThread.RunAfterRender` queue → swap → `OnPostRender`.

`Quit()` unloads scene, audio and all resources (including global), shuts down `WorkerPoolManager`, resets `ServiceLocator`.

## Scenes and scene graph

- Register scenes with `SceneManager.Register<T>()` inside `OnRegisterScenes`; loading an unregistered scene falls back to `ErrorScene`.
- `SceneManager.Load<T>()`, `Load<T, TParam>(arg)` (scene implements `ISceneWithArgs<TParam>`), `Reload()`, `LoadPrevious()`. Switching is deferred to the start of the next update.
- Load order: constructor → `LoadContent()` → `Start()`.
- Unload clears: scene commands and overlay elements, `Destroy()`, `UnloadContent()`, skybox and `LightSystem`, non-global `InputManager0` actions, **all `EventBus` subscribers**, `Camera.Main`, **all non-global resources**, `VisualDebug`, then the scene resource scope (leak report); then a forced GC.
- `Scene` is an abstract `Node3D` with `LoadContent`/`UnloadContent`.
- `Node3D`: `Start`, `Update`, `Render`, `OnGUI`, `Destroy`; recurse into enabled components then children. Exception: `Node3D.Render` only renders its own components and does not recurse — `BVHCuller` walks the tree and calls `Render()` per node.
- `Component`: `OnAttached`, `Start`, `OnUpdate`, `OnRender`, `OnGUI`, `OnDetached`; attach with `node.AttachComponent(c)`.

## Resources (`Resources.cs`)

- `Resources.Load<T>(path, global = false)`: cached per type; key is the path without extension with `/` separators, plus a short file-name alias.
- On failure it logs and returns the fallback from `ResourceFallbacks` (pink texture, error shader/mesh/clip, created in `EngineWindow.OnLoad`) — it does not throw. A type without a fallback throws `InvalidOperationException`.
- `Resources` itself is a plain registry without GPU work, so it is usable in tests.
- Non-global resources are disposed on every scene switch. Use `global: true` for anything that outlives a scene (all engine-owned resources).
- `Get<T>` loads on miss; `AddResource(name, res, global)` registers code-created resources.

### Resource lifetime (`ResourceScope`, `ResourceScopes`)

- Every resource has exactly one owner. Cached resources (`Load`/`Get`/`AddResource`, fallbacks) are owned by the cache: users never dispose them. Their `Dispose()` is ignored with a warning (`Resources.BlocksDispose`); the cache releases scene entries on scene change and global ones on exit (ref-counted when one object sits under several keys). Use `Resources.Release(res)` when a field may hold either a cached or a self-created resource: it disposes only uncached ones.
- New `Texture2D`/`Shader`/`Mesh`/`MeshBuffer`/`AudioClip` objects start in `ResourceScopes.Scene` (with the creator recorded in Debug builds). An object that keeps a resource and disposes it itself (renderers, fonts, atlases, previews, `Mesh` for its buffer) calls `ResourceScopes.Own(res)`; app-lifetime resources without an owner that disposes them go to `ResourceScopes.KeepForApp(res)` (disposed silently on exit). `Resources.AddResourceToDispose` hands a resource to the current scene.
- `SceneManager` ends the scene scope after `UnloadContent`, `Resources.UnloadAll` and `DisposalManager.ProcessDisposals`: anything still tracked is a leak, logged as `[Resources] Leaked scene resource ...` with its origin and disposed as a safety net. Fix leaks by disposing in the owner, never by relying on the net. `EngineWindow.Quit` calls `ResourceScopes.Shutdown()` (scene leaks reported, app scope disposed).

## Rendering

- Shaders are single files with `--Vert` / `--Frag` sections, loaded by path without extension; hot-reloaded via a file watcher (reload runs on the main thread). UBOs are bound automatically. Uniform locations are cached at link time; `Set*` does one dictionary lookup per call.
- Shader portability tests (GPU vendors differ: NVIDIA accepts code that AMD/Intel/macOS reject): every game shader file (`Spacebox.Tests/Shaders/ShaderCompileTests`) and every shader embedded in engine code (`Engine.Tests/Shaders/EmbeddedShaderCompileTests`, the sources are `internal` for the tests) is checked by `ShaderValidator` = the Khronos reference compiler glslang (Glslang.NET, test-only package; desktop GLSL, forward-compatible, per-stage parse and program link) plus `GlslPortabilityLint` (names removed from the core profile such as `texture2D`, `gl_FragColor`, `varying`). `ShaderPortabilityCanaryTests` keep a list of typical driver differences that must stay rejected. New shaders embedded in C# need a case in `EmbeddedShaderCompileTests`.
- Matrix convention is row-vector: `vec4(aPos, 1) * model * view * projection`; `SetMatrix4` transposes by default.
- `LightSystem` limits: `MAX_DIR = 4`, `MAX_POINT = 64`, `MAX_SPOT = 32`.
- Materials derive from `MaterialBase` (shader, color, render mode/queue, textures, `Apply(node)`).
- Large coordinates: build model matrices with `GetRenderModelMatrix` relative to `RenderSpace`.
- Wrap GPU work in `GPUDebug` groups and `Prof.Time(token)` scopes where useful.
- Offscreen rendering: `Graphics/RenderTexture.Render(camera, draw)` binds its FBO, swaps `Camera.Main`, pushes `GlobalUniforms` and restores everything; show it with a CanvasUI `TextureHandleRect` (flipped vertically). `OrbitViewCamera` is a non-main orbit camera (`Orbit`, `Zoom`, `Frame(center, radius)`).
- G-buffer: the scene FBO's attachment 1 holds view-space normals (`rgb`) and an AO mask (`a`: 0 none, 0.5 view-model, 1 world). Only materials with `WritesGBuffer = true` (Opaque/Cutout) write it; their shader must write `location = 1` (game include `includes/gbuffer.glsl`). A first-person model drawn with its own projection calls `ViewModelProjection.Set(projection)` each frame (reset before every scene render).
- SSAO: `PostProcessing/Ssao/SsaoEffect` (+ `SsaoSettings`, `SsaoPreset`, `SsaoKernel`, `SsaoTargets`, `SsaoProjection`); shaders are injected via `SsaoShaders`, settings via `Configure`. Effects that need scene depth/normals get `EngineWindow.SceneRenderer`. Upload uniform arrays with `Shader.SetVector3Array`.
- Color grading: `PostProcessing/ColorGrading/ColorGradingEffect` (brightness/gamma, contrast, saturation, film grain; `Configure(ColorGradingSettings)`, disabled while neutral, runs even when post processing is off). `Time.AlwaysCalculateFPS` keeps `Time.FPS` updated without the F3 overlay. `PostProcessing/CameraFeed/CameraFeedEffect`: security-camera look, shown while `Active` and `Intensity > 0`. `PostProcessing/Glare/LensGlareEffect`: lens flare around a screen point (`LightPosition` in NDC, `Color`), on while `Intensity > 0`.
- Transparency: renderers with a Fade/Transparent material submit to `Graphics/Transparency/TransparentQueue` (`TrySubmit` + `ITransparentRenderable.RenderTransparent`) during the scene render; the queue draws them after the opaque pass, sorted by `RenderQueue` then back to front. `RenderTexture.Render` opens its own nested scope. New transparent renderers should do the same instead of drawing immediately.
- `GLState` and `Texture2D.Use` cache GL state: code that changes blend/texture state with raw GL calls must restore it or reset the cache (`Texture2D.ResetBindingCache`, done after the canvas renderer). Set blend factors with `GLState.BlendFunc`; after raw blend calls call `GLState.InvalidateBlendFunc`.

## GUI and input

- All GUI is CanvasUI (no ImGui). `UIManager` keeps a stack of named windows (`Open`, `Toggle`, `CloseTop`, `IsOpen`); gate gameplay input on `IsUIMode` and the canvas `WantsPointer`/`WantsKeyboard`. The debug console is the `"debug"` window. Debug tools use `DebugCanvas` + `DarkTheme`; world-space debug drawing goes through `WorldDebugControl` (project with `WorldToCanvas`, draw with `CanvasShapes`/`CanvasDraw.Text`).
- `InputManager.LoadConfiguration` keeps the existing `InputAction` objects (and their `Subscribe` callbacks) and only replaces their bindings, so reloading the key config is safe at any time.
- `ParticleSystem.GloballyEnabled` hides and stops all particle systems (the particle setting). Post-processing effects that must always run (the passthrough `DefaultEffect`) override `IsRequired`; `PostProcessManager.Enabled = false` skips only the others.
- Input: named actions → `InputPro.InputManager.Instance` (JSON bindings, remappable); raw state → `Input.IsKey` / `IsKeyDown` / `Input.Mouse`. `InputManager0`/`InputAction0` are legacy (still used for engine F-keys).

## Threading and services

- GL calls only on the main thread (buffer/texture/shader creation **and** disposal).
- Static systems never create GPU objects in static constructors or field initializers: keep their bookkeeping GL-free and create GPU objects in an explicit `InitializeGpu()` called from `EngineWindow.OnLoad` (`ResourceFallbacks`, `LightSystem`, `VisualDebug`). This keeps them testable (`Engine.Tests` covers `SceneManager`, `Resources`, `Scene`) and prevents GL calls from worker threads that first touch a type.
- `WorkerPoolManager.Enqueue(action, Priority.High|Medium|Low, token)` returns a `Task`; general workers sleep on one semaphore and take the highest-priority item as soon as one is queued (no polling). Workers run at below-normal thread priority so the main thread keeps its frame time; jobs are `WorkItem<T>` (`WorkItems.cs`, the item is its own `TaskCompletionSource` with asynchronous continuations), cancelled tokens and jobs queued after `Shutdown` complete as cancelled.
- Main-thread marshalling inside the engine: `EngineWindow`'s main-thread action queue. (The game's `MainThreadDispatcher` lives in `Spacebox`, not here.)
- `DisposalManager`: thread-safe queue to defer GL disposal from worker threads; processed by the game scene.
- `EventBus`: struct events implementing `IEvent`, listeners `IEventListener<T>`, `Publish(ref e)`. Cleared on every scene switch — subscribe again in each scene.
- `ServiceLocator` (`Register`/`Get`/`TryGet`), `Pool<T>` (`Get`/`Release`), `ConcurrentPool<T>` (thread-safe `Rent`/`Return` with reset and a retain limit, for buffers shared by workers and the main thread), `TickTaskManager` (game ticks), `Debug` (`Log`/`Warning`/`Error`/`Success`, console on backtick, log file).

- `CanvasRoot`: `Stretch` (`StretchSettings`: `VirtualSize`, `Mode` Disabled/KeepAspect/Expand, `UiScale`, `MinScale`/`MaxScale`, `MinimumViewportSize` caps the scale so that logical size always fits, `ScaleStep`, `SafeMargins` in screen pixels, `MaxSafeAspect` centres the safe area on ultrawide screens; pure math in `CanvasStretch.Compute`), `ViewportRect`, `SafeRect`, layout only when dirty (property setters call `QueueLayout`, up to 3 passes), hit test (topmost, respects clip and mouse filter, a visible `Modal` layer blocks lower layers), hover/press/release dispatch with bubbling through `Pass` controls, scroll bubbles to the first handler, tooltip (`TooltipPanel`, a `PopupPanel` on the Tooltip layer next to the pointer; `TooltipTitle` in faux bold, `TooltipText`, optional `TooltipImage` with `TooltipImageSize`/`TooltipImageFlipV`, `TooltipContent` for any control shown under the text); `WantsPointer` for gating game input. - Layers: `root.Add(control, UiLayer.Hud)` / `root.Layer(UiLayer)` (`UiLayerRoot`, ordered Background < Hud < Windows < Popup < Modal < Tooltip < Debug). - Keyboard and editing: `CanvasRoot.Update(dt, PointerState, KeyboardFrame)` (typed text + `KeyPress` events with repeats from `Input.Text`/`TextInputBuffer`), focus (`Control.FocusMode` None/Click/All, `GrabFocus`, `FocusNext` on Tab, `WantsKeyboard`, `UnhandledKeyPress`), clipboard (`ICanvasClipboard`, window clipboard in `CanvasLayer`), `ClickCount` for double/triple clicks, `OnMouseMove` for drags, popups with `AutoHide`/`Owner` close on outside clicks. Text: `TextEditState` (pure editing model with undo), `LineEdit`, `TextEdit` (multi-line, line numbers). Controls: `NumberEdit`, `CheckBox`, `ItemList` (headers, icons, indent, clipped and scrolled), `ComboBox`, `PopupMenu`, `HSlider`, `HSeparator`/`VSeparator`, `ColorPickerButton`, `ConfirmDialog` (Modal layer), `TextureHandleRect` (raw GL texture handles, e.g. render targets). Containers: `TabContainer`, `SplitContainer`, `FoldableContainer`, `HFlowContainer` (wraps children into rows).
- Use: create a `CanvasLayer`, add controls to `layer.Root`, call `layer.Update(Time.Delta)` in the scene update and `layer.Render()` from `OnGUI`. No per-frame allocations in layout/draw; cache strings that change rarely.
- Caches (keep them valid when adding features): `GetThemeStyleBox`/`Color`/`Constant`/`Font`/`FontSize` results are cached per control and dropped whenever the global `ThemeVersion` changes; it is bumped by every `Theme` setter, `CanvasRoot.Theme`, `Control.Theme`, `ThemeTypeVariation`, `AddTheme*Override`/`RemoveThemeColorOverride` and every tree change (`AddChild`/`InsertChild`/`RemoveChild`/root change). New state that affects theme lookups must call `ThemeVersion.Invalidate()`. During `CanvasRoot.Layout` each control's `GetCombinedMinimumSize` is computed once per pass and recomputed after any `QueueLayout` or resize, so `GetMinimumSize` may only depend on state whose setters call `QueueLayout` (or on the control's size). `GlCanvasRenderer` multiplies the screen transform once per `Transform` change, not per quad. Measure UI changes with `Spacebox.Benchmarks/Engine/CanvasLayoutBenchmark` (`dotnet run -c Debug -p:Optimize=true --project Spacebox.Benchmarks -- --filter "*Benchmarks.Engine*"`, in-process short runs; without arguments `Program` runs its default benchmark).
- Demo: game scene `UiShowcaseScene` (`--ui-showcase`, or the dev panel scene list) with five interface variants in `Spacebox/Game/GUI/Showcase/` (`ShowcaseHost` builds the bar, HUD/windows/popup areas and help modal for the scene and for `Spacebox.Tests/GUI/ShowcaseLayoutTests`).

## Headless mode

- Window system: `Core/Platform/WindowSystemBootstrap.Initialize(requested, headless)` must run before the first window or `Monitors` call; it sets a logging GLFW error callback (OpenTK's default throws through native frames and aborts the process) and picks the GLFW platform from `WindowSystemRules` (Linux: Wayland session → Wayland then X11, else X11 then Wayland; headless → null platform). Check `EngineWindow.CanPositionWindow` before reading or setting window positions (Wayland has none). With the null platform the window has no context (`ContextAPI.NoAPI`) and `Graphics/Headless/NoOpGraphicsBindings` makes every GL call return 0; code that reads GL limits must tolerate 0.
- `Application.EnableHeadless()` (before the window is created; the game calls it for `--server`): `EngineWindow` skips rendering, post-processing, scene renderer, light/debug GPU init and `GlobalUniforms`; canvas layers draw nothing; `AudioDevice` opens no OpenAL device and `AudioClip`/`AudioSource`/`AudioListener` do nothing; `Texture2D` from files is a 1x1 CPU placeholder with `Handle` 0, other textures keep CPU pixels only; `Shader` does not compile; `MeshBuffer`/`Mesh`/`UniformBuffer`/`ParticleRenderer` create no GL objects; `TextureAtlas` registers images as 1x1 placeholders. New GPU or audio code must keep working with handle 0 / `Application.IsHeadless`.

## Which to use

- `Octree<T>` — bounds-based (world sectors, chunks). `PointOctree<T>` — point-based (drops, sector entities).
- Input: InputPro / `Input`, not `InputManager0`.

## Gotchas

- Scene switches are deferred and wipe EventBus listeners, non-global input actions and resources, lights and `Camera.Main`.
- `Node3D.Render` does not recurse; culling drives rendering. `BVHCuller` walks enabled nodes once per frame, computing each node's bounds (`IRenderBounds` or enabled collider volumes) as it goes; the main camera and its children are never culled.
- Engine code must not reference `Spacebox.*`; put reusable features here, game specifics in `Spacebox/`.
